## Optional additive verification command

From PowerShell, this command recomputes the accepted route/power checks and writes a new audit label; it does not launch Vivado or model inference. The selected map intentionally keeps the original stress scope described above. Choose a new label if this one already exists; the checker refuses to overwrite earlier audits.

```powershell
$taskPython = "C:/Users/Ritesh/rn_dps/.venv/Scripts/python.exe"
$taskWidth = "C:/Users/Ritesh/Documents/Codex/2026-10-08/oka/work/adaptive_snn_probe/validation_close/width16"
& $taskPython -B "$taskWidth/verify_selected_evidence_certified.py" --route-acceptance "$taskWidth/route_resolved_acceptance_a1.json" --e7-hardware "$taskWidth/lutceil_e7/hardware/route12_e7_close_a0/hardware.json" --power-map "$taskWidth/energy_partition_aggregate_power_map_partitioned_all_a0.json" --label reproduce_review_20261011 --strict-primary
```

For an actual new native, route or delayed-replay run, the root task owns the serial vendor launch window and must supply a fresh attempt label/output directory. Existing runners record their exact commands and environment in `provenance.json` and `tool_*.job.json`. Preserve every accepted artifact. The established gates require1.2GiB simulation working RAM or2.3GiB export/power working RAM plus0.15GiB headroom; rerouting can require more. Do not stop unrelated applications. Reuse certified structural EOF repairs and the unchanged declared replay protocol, never suppress timing checks to manufacture acceptance.

This guide indexes reproducibility evidence. It does not convert access-limited literature, unmeasured model-specific constant hardware or excluded source integration into completed readiness claims.
