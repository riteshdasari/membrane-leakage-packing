# Independent operand-isolation mechanism review

The prepared V3/ISOLATE=1 core contains exactly two reviewed changes from the frozen core: its renamed module/default parameters, and zero isolation of both selected membrane high bits and the signed ±1 adjustment. The classifier, lane selection, DSP, output assembly, scheduler, registers, reset and handshake logic remain unchanged. The isolation enable is `v2 && (|work_mask)` and does not depend on `out_ready` or `output_space`.

The reproducible scalar review covers all 524,288 signed11 U / signed8 I pairs. It checks Euclidean quotient/remainder reconstruction and both exact fast paths. For all 229,376 exceptional pairs, carry differs from current sign, making `hI + carry` exactly ±1. The isolated five-bit sum preserves that exact quotient when enabled and becomes zero when disabled. This introduces no rounding or output precision change.

Both source high-part write sites remain guarded by `correction_step && selected_mask[l]`. That write condition implies the isolation enable. A separate enumeration covers all 131,072 binary combinations of bad/pending masks, busy, v2, output valid/ready and reset; this is a superset of reachable controller states. The last busy correction stays enabled even when it advances the pipeline. Backpressured exceptions deliberately remain enabled, while output writes are blocked. Reset overrides writes. Neither isolated operand nor corrected high feeds the classifier or scheduler, so the source change adds no combinational feedback.

These checks establish scalar algebra, an exact source-diff boundary and a combinational write implication. They do not constitute sequential RTL equivalence, reset/backpressure simulation, a formal reachability proof or timing verification. The root must separately check full traces, correction/freezing counts, backpressure/reset behavior and SDF replay. After routing, it must inspect the actual arithmetic cone and measured activity: source isolation alone does not prove switching suppression.

The first core has no KEEP or DONT_TOUCH added for isolation. Original timing-fixture preservation attributes are retained identically. Gating after selection minimizes added logic, but upstream selection and classification still toggle. With only +0.108 ns setup slack in frozen V3, added enable-to-adder depth and glitches are material concerns. Synthesis may absorb or rewrite gates because their disabled values are unused; a disappeared source net name alone is insufficient evidence of failure. If explicit preservation later becomes necessary, scope it narrowly to the isolated operands and measure its cost. [AMD KEEP](https://docs.amd.com/r/en-US/ug901-vivado-synthesis/KEEP) distinguishes synthesis preservation from the implementation preservation of [DONT_TOUCH](https://docs.amd.com/r/2025.1-English/ug901-vivado-synthesis/DONT_TOUCH).

Energy benefit remains unmeasured. Frozen V3 would need roughly 2.821 mW less average whole-fixture dynamic power to match fixed V2 energy at its unchanged duration. Its exported unclocked fabric logic and signal power total only 2.524 mW, and the corrector is a subset of that fabric. Closing the full fixed gap through corrector isolation alone therefore appears unlikely. This is a plausibility observation, not a formal lower bound after remapping and routing. Report any measured V3 improvement separately from superiority over V2.

Run `review_operand_isolation.py` once to produce `review_checks.json`, then `review_operand_isolation.py --check` to reproduce the exact saved result without writing. The script launches no HDL tools and reads the architecture sources without modifying them. This review is an independent subagent mechanism check; power/activity and hardware results belong to the root's separate execution evidence.
