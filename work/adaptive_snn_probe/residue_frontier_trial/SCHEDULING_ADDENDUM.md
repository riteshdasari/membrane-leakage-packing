# Bounded simulator concurrency for the user's speed request

The user explicitly requested faster completion through coordinated parallel
work while preserving every research check. After measuring the running XSim
process tree at approximately0.26GiB, root permits two independent routed
timing replays to overlap. The original startup-invalid replay may still finish
as a third small simulator. All Vivado synthesis/implementation/export/power
jobs remain serialized, with the existing2.3GiB start-RAM gate. No user apps
are stopped and no data, arithmetic, clock period, measured interval, mapping
flow or audit rule changes because of concurrency. Every job retains its own
directory, TEMP/TMP, sources, activity and memory record. The original serial
contract is preserved as the original scheduling decision; this addendum
records the bounded scheduling adjustment made to satisfy the user's speed
instruction. The phase-preserving startup-TB correction is separately pinned.
