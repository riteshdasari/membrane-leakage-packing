# OTTT capture a0: retained distribution failure and additive protocol correction

The `ottt_random_stratified_a0` capture passed all actual-feedback, 64-logit and full-count replay checks. Its 262,440 nonzero operands in 5,120 short windows failed the unchanged issue-gap distribution gate: 54.1682% sampled adaptive issue overhead versus 55.4999% in the original full64 stream, an absolute difference of 1.3318 percentage points exceeding the 1-point limit. All five other distribution gates passed. This attempt is retained and is **not admitted to representative hardware energy**.

Restarting fixed packing at every window creates 1,260 additional issue slots from odd window lengths. Relative to attributing half of each original full-stream pair to each selected endpoint, adaptive restarting adds 562.5 slots. The same selected operands retain a 55.2199% overhead under their original schedule attribution (55.2058% with the declared expansion weights). This explains most, but not all, of the failed gap through asymmetric window-boundary padding. The attribution is a diagnostic; it does not retroactively change the emitted RTL schedule or admit a0.

The additive v2 protocol is declared before its inference in `ottt_capture_preparation_v2.json`. It preserves target budget262,144, seed417839, model/checkpoint/coefficients/units, all feedback/count checks and all six original distribution limits. Reducing windows per nonzero frame from8 to2 makes each selected contiguous window about four times longer and reduces restart boundary density. No favorable membrane values, seeds or accuracy results are selected. The exact source diff is `ottt_capture_protocol_v2.diff`; a fresh a1 must independently pass all original gates before energy admission.
