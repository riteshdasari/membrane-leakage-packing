# Bounded independent review of the prepared BNTT benchmark

Reviewed the released `bntt_visual_source/model.py` and `main.py`, `bntt_integer.py`, `run_bntt.py`, imported arithmetic source `ottt_integer_v2.py`, acquisition/contract/subset metadata and checkpoint structure admission on 2026-10-10. **No Torch import, model inference or vendor tool launch occurred in this review.** This source review is preparation evidence, not an accepted benchmark result.

## Outcome

No meaningful recurrence, pooling, timestep-BN, readout, sample identity or packed-versus-scalar comparison discrepancy was identified in the prepared source. One minor source-admission omission was reported to the benchmark owner and repaired before this final snapshot: `run_bntt.py` now asserts each of the four released-source file hashes against `bntt_acquisition.json`, before checkpoint/model construction. The final reviewed source passes those four frozen hashes and both downloaded asset hashes.

Reproducible bounded checks are in `check_bntt_source_review.py` and `bntt_independent_source_checks.json`. The script parses and syntax-compiles sources without executing them, independently constructs the expected CPU-placement AST, verifies selected-image/class metadata directly from the pinned archive, and checks constant253 arithmetic using independent integer division. It does not import any benchmark module.

## Neuron semantics and source faithfulness

- The author source evaluates the spike and reset from **old** membrane: `mem_thr=U_old/threshold-1`; `spike=(mem_thr>0)`; reset subtracts threshold where that condition holds; only then is the membrane charged. With threshold1, the declared Q8 adapter correctly uses **`old>256`**, not equality firing and not a newly charged-state comparison. Its stored update is `ceil(253*old/256)+RNE(current*256)-256*spike_old`. It returns the old spike to the next layer at the same timestep. This preserves the original delayed firing/reset arrangement within the explicitly converted integer model.
- `RNE(.99*256)=253`; `253/256=.98828125`, which differs from the original FP32 coefficient0.99. Neuron conversion is therefore approximate relative to the FP32 model. The runner separately records original-FP32, plain-integer and packed-integer predictions/logits. It cannot use packed/plain equality as a claim that FP32 SNN outputs were preserved.
- The CPU original uses the unchanged author model AST after removal of **22 parameterless `.cuda()` placement calls**. The independent expected transformed AST hash is `a0f710120cb45f371a1e21a4a924854922a185418ed857ebc97f097c7f5e901f`. No neuron equation, operator order, BN parameters or random input arithmetic changes appear in that transformation. Syntax compilation succeeds. Actual CPU-versus-author-CUDA accuracy equivalence is not asserted.
- The adapter has the source's eight convolutional hidden layers plus fc1, uses each layer's `bn*_list[t]` for t0–29, and reuses the loaded convolution/linear/pooling/BN modules. Pooling after zero-based convolution indices0,1,3,5 corresponds exactly to source conv1,2,4,6. The final pooling is the source's adaptive average pool followed by flattening. Source-defined `pool5` is unused in both forwards. fc1 uses `bnfc_list[t]`; fc2 accumulates floating voltages without leakage/reset and divides by30. Original temporary per-step visualization voltages and saved-feature hooks do not affect the returned logits.
- Although the adapter evaluates convolution/BN current before calling its update, whereas the original computes the old spike first, the old membrane is unchanged and these reused modules are in eval mode with no stochastic or in-place state dependence. The effective equation and forwarded old spike therefore agree. Explicit contiguous spike tensors also preserve a common input layout for the two integer executions.

## Random draws, identities and preprocessing

- Original CPU `PoissonGen` and the adapter both draw `torch.rand_like(inp)` once per timestep and compute `sign(inp)*[2*rand <= abs(inp)]`. Neither forward adds another RNG draw. All three models are constructed/loaded before per-image reseeding. Each execution resets the same CPU generator to `2021+canonical_validation_index`, so draws are aligned by source construction. Direct runtime draw/state agreement remains part of the probe; this review did not execute those draws.
- The deterministic full subset is 64 unique indices sampled without replacement from10,000 with NumPy generator seed20211001, then sorted. All64 indices, suffix-based filenames, annotation class IDs, sorted class indices and Poisson seeds match the predeclared file. JPEG hashes were independently recorded from the pinned validation archive. Smaller prefix runs are declared semantic probes, not estimates from a separately uniform N-image sample.
- The runner's RGB decode and functional `to_tensor` followed by ImageNet normalization match the original inference `ImageFolder` transform. Inputs stay64x64. The original visualization loader's128x128 resize is not used. Sorted canonical class IDs match `ImageFolder` ordering. Data come from the held-out validation annotations, without training/test substitution or range-dependent selection.

## Exactness and hardware-domain gates

- Both integer executions begin each image with zero int64 membranes, and both use the same rounding of effective FP32 convolution/BN currents. Plain leakage uses scalar ceiling division. Packed leakage calls the existing E5 executor; actual decoded results feed the stored state rather than merely being logged. That executor compares every decoded result against scalar ceiling and asserts zero mismatches, including scalar fallback and zero bypass.
- The plain run retains each hidden layer's stored membrane and old-spike tensor at every timestep. The packed run compares the layer name, timestep, every stored-state element and every spike element against that reference, then releases each reference. Its final comparison-index assertion requires all expected updates to be consumed. The runner requires cumulative state/spike mismatches to be zero and complete integer-versus-packed output logits to be equal. No early exit is present.
- Old membrane and post-reset stored membrane values outside signed16 are counted separately, across all updates. `fixed16_hardware_domain_supported` is true only if both counts are zero. The software's larger signed24 diagnostic bound is asserted and no clipping, saturation, wrapping or representation rescaling is performed. The imported arithmetic counter named `signed12_exceptions` is historical metadata; the separate signed16 counts are the hardware-domain decision. A software run with any signed16 exception cannot be presented as accepted full16 hardware-model support.
- Safe loading retains `weights_only=True` and only the audited NumPy scalar/dtype constructors needed by metadata. Model state dictionaries load strictly; the three loaded models' state tensors are checked equal. Legacy pickle/Torch compatibility, actual tensor shapes and the one-image inference gate are still untested by this source-only review and must not be claimed passed.

## Constant-coefficient control and contribution scope

For all signed16 integers U, independently checked **65,536 cases with zero mismatches**:

`ceil(253*U/256) = U - floor(3*U/256)`.

Form `3U=(U<<1)+U` in signed18 (range−98,304…98,301), shift arithmetically by8, then subtract at sufficient width. The identity includes negative values and exact multiples. This is a strong zero-DSP constant-specific control even though0.99 itself is not a power-of-two coefficient. Uniform beta253 TinyImageNet validation establishes applicability and conversion behavior; it does **not** establish that a general DSP multiplier is necessary or that adaptive DSP packing has a workload hardware advantage. General runtime-coefficient energy/area comparisons retain their separate, explicitly declared operation contract. There is no coefficient retuning to evade the constant control.
